# บทที่ 1 · GPIO: LED, ปุ่ม และ `millis()`

## เรียนอะไร

- `pinMode()`, `digitalWrite()`, `digitalRead()`
- **ทำไมไม่ใช้ `delay()`**: ระหว่าง `delay(500)` ESP32 ทำอย่างอื่นไม่ได้เลย ทั้งอ่านปุ่ม อ่านเซ็นเซอร์ และรักษาการเชื่อมต่อ MQTT ในบทหลัง ๆ จึงใช้รูปแบบนี้แทน
  ```cpp
  if (millis() - lastTime >= INTERVAL) {
    lastTime = millis();
    // ทำงานตามรอบ
  }
  ```
  การลบแบบ `millis() - lastTime` ยังถูกต้องแม้ `millis()` วนกลับเป็น 0 (ทุก ~49 วัน)
- **Debounce**: หน้าสัมผัสปุ่มเด้งหลายครั้งในไม่กี่มิลลิวินาที จึงต้องรอให้ค่านิ่ง (30 ms) ก่อนเชื่อ
- **Edge detection**: สนใจ "จังหวะที่เปลี่ยนเป็นกด" ไม่ใช่ "กำลังกดอยู่" — ฟังก์ชัน `buttonPressed()` คืน `true` ครั้งเดียวต่อการกด

## ฮาร์ดแวร์

ใช้ของบนบอร์ดอย่างเดียว: LED GPIO18 และปุ่ม BUTTON GPIO0
(GPIO0 มีตัวต้านทาน pull-up บนบอร์ดแล้ว จึงใช้ `INPUT` ได้ ถ้าใช้ปุ่มภายนอกบนพอร์ต K3 GPIO5 ให้ใช้ `INPUT_PULLUP`)

## ลองทำ

อัปโหลด [L01_gpio.ino](L01_gpio.ino) แล้วกด BUTTON — LED จะสลับระหว่างกระพริบช้า เร็ว และดับ

## แบบฝึกหัด

1. เพิ่มโหมดที่ 4 "ติดค้าง"
2. **กดค้าง 2 วินาที** ให้กลับไปโหมดแรก (ใบ้: จำเวลาที่เริ่มกดไว้)
3. ต่อ ZX-SWITCH01 ที่พอร์ต K3 (GPIO5) และ ZX-LED ที่ K5 (GPIO23) ให้ปุ่มภายนอกควบคุม LED ภายนอกแยกจากปุ่มบนบอร์ด — ทั้งสองคู่ต้องทำงานพร้อมกันได้โดยไม่รอกัน
4. คิดต่อกับโจทย์: ถ้าเกษตรกรกดปุ่มเพื่อ "เริ่มล็อตใหม่" ควรใช้กดสั้นหรือกดค้าง เพราะอะไร
