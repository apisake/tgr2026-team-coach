# บทที่ 9 · งานรวม: ตัวควบคุมตู้อบเมล็ดกาแฟ

รวมทุกบทเป็น **firmware template** ตามเป้าหมาย Phase 1 ในแผน: Wi-Fi + MQTT + NTP + JSON + reconnect + config แยกไฟล์ + drying controller
ใช้เป็นจุดเริ่มต้นของโค้ด ESP32 ในวันแข่งได้ — เปลี่ยนเซ็นเซอร์และกฎควบคุมตามโจทย์จริง โครงที่เหลือใช้ต่อได้ทั้งหมด

> ตัวเลขใน `config.h` (45 °C, ความชื้นเป้าหมาย 12%) เป็นค่าตั้งต้นสำหรับซ้อมเท่านั้น ต้องตรวจกับงานค้นคว้า R3/R4 ก่อนใช้นำเสนอ

## ระบบทำอะไร

```
ZX-MCP9701 (K7) ─┐                          ┌─▶ ZX-LED K5 = ฮีตเตอร์ (เปิด/ปิด แบบ hysteresis)
ZX-SOIL    (K8) ─┼─▶ อ่าน + กรอง ─▶ control ─┼─▶ ZX-LED K4 = พัดลม (PWM ตามความร้อนเกิน)
BUTTON  (GPIO0) ─┘                          ├─▶ เสียง + LED สถานะ
                                            ├─▶ OLED
                       MQTT cmd ──▶         └─▶ MQTT telemetry / event / status
```

| สถานะ | ฮีตเตอร์ | พัดลม | เปลี่ยนเมื่อ |
|---|---|---|---|
| `idle` | ปิด | ปิด | กดปุ่ม หรือ `{"start":true}` → `drying` |
| `drying` | hysteresis รอบ setpoint | ≥ `FAN_MIN_DUTY` และเร่งเมื่อร้อนเกิน | ความชื้น ≤ เป้า → `done` · ร้อนเกิน `TEMP_MAX_C` หรือสายเซ็นเซอร์หลุด → `fault` · กดปุ่ม → `idle` |
| `done` | ปิด | ปิด | ส่ง `lot_id` ใหม่ → `idle` |
| `fault` | **ปิดทันที** | เต็มที่ถ้าร้อนเกิน | กดปุ่ม หรือ `{"reset":true}` → `idle` |

## สิ่งใหม่ในบทนี้

- **State machine** — ทุกการตัดสินใจขึ้นกับสถานะปัจจุบัน และทุกครั้งที่เปลี่ยนสถานะจะส่ง `event` ให้ service บันทึกเป็นประวัติของล็อต (traceability)
- **Hysteresis** — เปิดฮีตเตอร์เมื่อต่ำกว่า `SP − band` ปิดเมื่อสูงกว่า `SP + band` ระหว่างนั้นคงสถานะเดิม รีเลย์จึงไม่สลับถี่จนพัง
- **Fail-safe** — ฮีตเตอร์ปิดตอนบูตเสมอ, เซ็นเซอร์อ่านค่าผิดปกติ = fault, เปลี่ยน `lot_id` ระหว่างอบไม่ได้
- **Watchdog** — ถ้า `loop()` ค้างเกิน 15 วินาที บอร์ดรีเซ็ตตัวเองและกลับสู่สถานะปลอดภัย
- **ตั้งค่าแยกไฟล์** — แก้ `config.h` ไฟล์เดียว ไม่ต้องแตะโค้ดควบคุม
- **Topic `event`** แยกจาก `telemetry` — ข้อมูลต่อเนื่องกับเหตุการณ์สำคัญมีการใช้งานต่างกัน

## Topic และคำสั่ง

| Topic | ตัวอย่าง |
|---|---|
| `.../telemetry` | `{"lot_id":"L-001","node_id":"esp32-a1b2c3","ts":"2026-11-17T07:05:09Z","seq":18,"state":"drying","temp_c":44.2,"moist_pct":31.5,"setpoint_c":45,"target_pct":12,"heater":true,"fan_duty":80,"rssi":-61,"uptime_ms":95211}` |
| `.../event` | `{"lot_id":"L-001",...,"event":"state","state":"fault","detail":"over temp"}` |
| `.../status` | `online` / `offline` (retain + LWT) |
| `.../cmd` | `{"lot_id":"L-002"}` `{"start":true}` `{"stop":true}` `{"reset":true}` `{"setpoint_c":42,"band_c":1.5,"target_pct":12}` |

## ลองทำ

1. แก้ `config.h` (Wi-Fi, IP ของ broker, ค่า calibrate ZX-SOIL จากบทที่ 5) แล้วอัปโหลด
2. เปิด `mosquitto_sub -h <pi> -t "tgr2026/#" -v` ไว้ตลอด
3. กด BUTTON เพื่อเริ่มอบ — ZX-LED ฮีตเตอร์ติดเพราะอุณหภูมิห้องต่ำกว่า setpoint
4. ส่ง `{"setpoint_c":28}` แล้วกำหัววัดอุณหภูมิ — ฮีตเตอร์ดับ และพัดลมสว่างขึ้นเมื่ออุณหภูมิสูงขึ้น
5. ถอดสาย ZX-MCP9701 ระหว่างอบ → `fault: temp sensor` และมีเสียงเตือน แล้วกด BUTTON เพื่อรีเซ็ต
6. ให้ ZX-SOIL แห้งลง (ยกออกจากน้ำ/ดินชื้น) จนต่ำกว่า `target_pct` → `done`

## แบบฝึกหัด (ซ้อมแบบโจทย์วันแข่ง)

1. **เปลี่ยนเซ็นเซอร์:** ใช้ SHT3x จากบทที่ 6 วัดอุณหภูมิและความชื้นสัมพัทธ์ของอากาศในตู้แทน ZX-MCP9701 และเพิ่ม `rh_pct` ใน telemetry
2. **น้ำหนัก:** เพิ่ม HX711 + load cell (ไลบรารี `HX711` ของ bogde) แล้วคำนวณ % น้ำหนักที่ลดลงจากตอนเริ่มอบ — ใช้เป็นเงื่อนไข `done` แทน ZX-SOIL
3. **ปิดลูปจาก AI/service:** ให้ service ฝั่ง Python ส่ง `setpoint_c` ใหม่ทุก 1 นาทีตามสภาพอากาศ (ฝนตก → ลด setpoint, เปิดพัดลมแรงขึ้น)
4. **PID:** เปลี่ยนฮีตเตอร์จาก on/off เป็น PWM แบบ PID (ใบ้: เริ่มจาก P อย่างเดียว แล้วเพิ่ม I) เปรียบเทียบกราฟอุณหภูมิกับ hysteresis
5. **Surprise จำลอง:** ให้เพื่อนเปลี่ยน Data Contract กลางทาง (เช่น เปลี่ยนชื่อ field `temp_c` → `air_temp`, เพิ่ม `farm_id`) แล้วจับเวลาว่าแก้และทดสอบเสร็จภายในกี่นาที
